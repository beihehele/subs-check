# v3.0.1 — 开箱即用示例与反向代理子路径修复

本次发布基于 `dev` 分支，是 `v3.0.0` 之后的修复版本。容器镜像为 `ghcr.io/beihehele/subs-check:3.0.1`，平台为 `linux/amd64` 和 `linux/arm64`；发布构建成功后同时更新 `latest`。本仓库当前发布流程不提供预编译二进制附件，也不发布 Docker Hub 镜像。

## 修复内容

- `config/config.example.yaml` 恢复为开箱即用：包含公开订阅示例、hybrid 地区分配、历史质量、媒体检测、历史节点保留、失效订阅跳过、测速阈值与复测等推荐值，复制为 `config.yaml` 后可直接运行。原独立的 `config.example.recommended.yaml` 已合并进主示例并删除。
- 新增 `web-base-path` 配置，支持反向代理子路径部署。填写 `web-base-path: /subs-check` 后，应用会同时在根路径和该前缀下注册静态资源、API 与管理页，代理剥离或不剥离前缀都可以正常加载 JS/CSS。
- 同时注册 `/admin/` 与 `/admin/results/`，避免代理或浏览器带尾斜杠访问时被重定向到丢失前缀的路径。
- 新增反向代理测试，覆盖剥离前缀、保留前缀和尾斜杠访问。
- CI 增加 Buildx，使 amd64 / arm64 多平台 Docker 构建可以正常执行。

## 升级步骤

1. 备份现有配置、配置目录下的缓存、输出目录和容器启动参数。
2. 将服务镜像改为 `ghcr.io/beihehele/subs-check:3.0.1`，保持原端口、环境变量和卷映射。
3. 反向代理用户按以下方式二选一：

   代理剥离前缀时保持默认配置即可，nginx 示例：

   ```nginx
   location /subs-check/ {
       proxy_pass http://127.0.0.1:8199/;
   }
   ```

   代理保留前缀时设置 `web-base-path`：

   ```yaml
   web-base-path: /subs-check
   ```

   ```nginx
   location /subs-check/ {
       proxy_pass http://127.0.0.1:8199;
   }
   ```

   不要只代理 `/admin`；`/static` 和 `/api` 必须走同一个前缀，否则控制面板会出现 JS/CSS 404。

4. 确认配置校验通过并完成一轮检测，再刷新客户端订阅。

## 兼容性

- 已有配置不会被示例文件覆盖；`web-base-path` 留空时行为与 `v3.0.0` 一致。
- 从 `v3.0.0` 升级不需要迁移配置。
- 仅支持 `linux/amd64` 和 `linux/arm64`；不支持 `linux/arm/v7`。

## 回退

将镜像改回 `ghcr.io/beihehele/subs-check:3.0.0`，恢复备份配置并重建容器。保留新缓存备份，不要删除卷或使用 `docker compose down -v`。
