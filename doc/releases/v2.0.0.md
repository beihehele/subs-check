# v2.0.0 — Telegram 原生检测与节点策略改进

本次发布基于 dev 分支，包含 master 同步以及节点检测、筛选、命名和订阅统计改进。容器镜像为 `ghcr.io/beihehele/subs-check:2.0.0`，平台为 `linux/amd64` 和 `linux/arm64`；发布构建成功后同时更新 `latest`。本仓库当前发布流程不提供预编译二进制附件。

## 更新内容

- 新增 Telegram 原生 MTProto 初始握手检测，通过后名称追加 `TG`；校验响应结构和随机 nonce，不以网站或 TCP 端口连通代替协议检测。
- 生成名称不再追加 D+/GM/CL/SP；这些平台仍可显式启用，在结果页查看并参与结构化筛选。`0%` 仍是 IP 风险值，不是丢包率。
- 增加地区、协议、延迟、IP 风险和平台的结构化筛选；不同条件同时满足，未知结果不会被视为通过。无效规则在加载和保存配置时被拒绝。
- 增加全局质量优先、地区保底加权分配、来源/IP 配额、历史质量平滑和新节点探索名额。旧配置未启用这些选项时继续采用地区均衡策略。
- 增加稳定名称模式 `SC-<固定ID>`；默认 compact 模式保留地区序号和检测标签。统一地区分组和命名依据，合并 UK/GB，修复地区查询失败后的重排问题。
- 去重覆盖完整连接参数，避免误合并不同协议、WS path、gRPC 等连接；同节点归属多个订阅时保留全部来源。
- 订阅统计拆分为存活、达标、入选。筛选和限额不再使健康订阅被判死；协议规则排除的订阅不算拉取失败，取消检测不更新健康历史。
- 测速校验 HTTP 状态、有效样本大小及异常断流；支持最低速度附近的三次中位数复测。
- 平台探测未给出明确结论时显示未知，避免将网络异常当作明确封禁；订阅统计页对来源文本进行 HTML 转义。
- 公开导出不携带订阅来源 URL；复测快照转入配置旁的私有缓存。配置重新加载后删除的规则不再残留。
- 合入 master 的管理页、结果页、订阅导出与缓存改进，并保留 dev 的地区配额和订阅统计功能。

## 升级步骤

1. 备份现有配置、配置目录下的缓存、输出目录和容器启动参数。保留当前镜像版本以便回退。
2. 按需修改原配置，不要用示例文件覆盖订阅地址、API Key、保存凭据或个人规则。启用 TG 的最小配置：

   ```yaml
   media-check: true
   platforms: [iprisk, youtube, netflix, openai, telegram]
   rename-node: true
   name-mode: compact
   ```

   如果需要保留 TikTok 等检测，将其并入已有列表；显式配置的 platforms 不会自动新增 telegram。不再需要的 disney/gemini/claude/spotify 可从列表移除以减少请求。

3. Docker Compose 用户将服务镜像改为 `ghcr.io/beihehele/subs-check:2.0.0`，保持原端口、环境变量和卷映射，然后运行：

   ```bash
   docker compose pull subs-check
   docker compose up -d subs-check
   docker compose logs --tail=100 subs-check
   ```

   服务名不是 subs-check 时替换为实际服务名。使用 docker run 的用户拉取同一固定版本镜像，按原参数重建容器。持久化 `/app/config` 和 `/app/output`。源码用户检出 `v2.0.0` 后按 README 构建，使用 go.mod 要求的 Go 版本。

4. 确认启动时配置校验通过，完成一轮检测，再刷新客户端订阅。检查 TG 标签、节点数量、地区顺序及管理页的存活/检测、达标、入选统计。

## 兼容性与迁移

- 旧 filter 中依赖 D+/GM/CL/SP 的表达式需要迁移，否则不再匹配这些自动生成的标签。需要保留某平台筛选时，显式启用该平台并配置 `node-filter.require-platforms`。平台列表表示全部要求；原 filter 列表仍表示任一匹配。
- 非法正则、未知或重复平台、未启用却被 require-platforms 要求的平台会使配置验证失败。配置热加载失败时保留上一份有效配置。
- 可选推荐配置 `config.example.recommended.yaml` 启用了 hybrid、历史质量及边界测速复测；默认示例和已有配置缺省时不会自动切换。复测会增加边界节点的流量和耗时。
- 完整连接参数去重可能使节点数增加。地区序号会随本轮候选变化；开启 stable 后名称会一次性切换，客户端需重新选择节点。stable 不把 TG 等动态标签拼入名称，结果页仍能查看检测结果。
- 新历史快照写入 `<配置目录>/cache/<配置名>/history/`，质量历史写入同级 `node-quality.json`。干净部署不读取旧 `output/history`；确保配置目录可写且持久化。
- TG 仅证明至少一个 Telegram 数据中心的原生初始握手可达，不保证账号登录、全部数据中心、下载或语音可用。地区来源标为“原名称推断”时不代表实测出口位置。

完整参数见[节点策略说明](https://github.com/beihehele/subs-check/blob/v2.0.0/doc/node-strategy.md)和[示例配置](https://github.com/beihehele/subs-check/blob/v2.0.0/config/config.example.yaml)。可选推荐参数与公开订阅示例见 `config/config.example.recommended.yaml`。

## 回退

将镜像改回升级前固定版本（从上一正式版升级时为 `ghcr.io/beihehele/subs-check:1.0.4`），恢复备份配置并重建容器。保留新缓存备份；旧版不读取新的私有历史目录。不要删除卷或使用 `docker compose down -v`。回退后重新检测并刷新客户端订阅。

## 验证范围

发布前执行全量 Go 测试、go vet、真实 Sub-Store 集成测试及页面脚本语法检查。Telegram 使用模拟协议服务覆盖有效响应、错误 nonce、错误结构、HTTP 响应、超长/截断数据和超时；未将模拟测试等同于真实订阅节点的在线可用性测试。
